01 / PROBLEM STATEMENT

Why this work exists

Extreme downside days are rare, so random train/test splits and headline accuracy can create misleading confidence. The project tests whether only pre-decision information can identify QQQ tail events.

Data and source material

  • QQQ daily OHLCV beginning in January 2000
  • 6,431 engineered observations with 20 lagged features
  • 55 extreme-day labels overall and 24 in the common out-of-sample window

02 / MY CONTRIBUTION

What I implemented

Expanding annual walk-forward evaluation compares logistic regression, random forest and XGBoost using only pre-decision information.

Implemented capabilities

  • 20 lagged features
  • 5,294 out-of-sample predictions
  • Rare-event PR-AUC evaluation
  • Interactive probability explorer

04 / METHODOLOGY & IMPLEMENTATION

Decisions that shape the system

  • Rolling inputs are shifted by one day to keep predictors observable before each decision.
  • Logistic Regression supplies a standardized linear baseline; Random Forest uses balanced subsamples; XGBoost uses shallow regularized trees.
  • PR-AUC is primary because accuracy is dominated by normal days.
  • The common comparison window contains 5,294 chronologically ordered out-of-sample predictions.

06 / CHALLENGES & LIMITATIONS

Where the evidence stops

  • Only 24 extreme days occur in the common out-of-sample period.
  • Conclusions are sensitive to the quantile-based crash definition.
  • Evidence comes from one instrument and does not model execution frictions or a live decision process.
MISSING EVIDENCE

No cross-asset generalization study or live deployment evidence.

07 / WHAT THIS DEMONSTRATES

Engineering signal

Rare-event modelling, leakage control, walk-forward evaluation, appropriate metric selection, and restrained interpretation under a small positive sample.
